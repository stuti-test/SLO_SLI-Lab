# Checkout SLO Lab: SLIs, SLO and Burn-Rate Alerts

A hands-on SRE lab using the OpenTelemetry Demo. I defined 2 SLIs and 1 SLO
for the `checkout` service and created fast-burn and slow-burn alerts in Grafana.

## Environment
- OpenTelemetry Demo (cloned from open-telemetry/opentelemetry-demo, [version/date])
- Docker Desktop (WSL 2), Prometheus and Grafana from the demo's compose.observability.yaml
- Metrics: `traces_span_metrics_calls_total`, `traces_span_metrics_duration_milliseconds_*`
  (generated by the collector's spanmetrics connector)

## Service chosen
`checkout`, operation `PlaceOrder` ([confirmed span_name]). It is the revenue path
and depends on payment, shipping, email and cart, so it reflects downstream health.

## SLIs
| SLI | Definition |
|---|---|
| Availability | % of PlaceOrder calls that do not end in STATUS_CODE_ERROR |
| Latency | % of PlaceOrder calls completing in under 1000 ms |

## SLO
**99.5% availability over a rolling 30 days.** Error budget = 0.5%.

## Burn-rate alerts
| Alert | Burn rate | Error-ratio threshold | Production windows | Lab windows | Severity |
|---|---|---|---|---|---|
| Fast burn | 14.4x | 7.2% | 1h / 5m | 15m / 5m | page |
| Slow burn | 6x | 3% | 6h / 30m | 1h / 10m | ticket |

Threshold = burn rate x 0.005. An alert fires only when both the long and short
window exceed the threshold. The long window shows the problem is sustained, and
the short window shows it is still happening, so the alert resets quickly after a fix.
Windows were shortened in the lab because Prometheus had only just started collecting data.

## How I tested
1. Generated steady traffic with the load generator.
2. Enabled the payment failure flag at [X]% in flagd.
3. Observed the error ratio rise, the fast-burn alert go Normal -> Pending -> Firing
   after about [N] minutes.
4. Disabled the flag and observed recovery.

## What I learned
- How to turn traces into SLIs with spanmetrics
- SLOs, error budgets and burn rate
- Why multi-window, multi-burn-rate alerting beats a simple threshold
- Troubleshooting Docker port conflicts, health checks and networking

## Issues I hit
- The payment image has no shell, so its health check could never pass. I started
  dependent services with `docker compose up -d --no-deps`.
